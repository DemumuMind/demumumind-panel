# Contributing to DemumuMind Panel

Спасибо, что решили внести вклад. Несколько правил, чтобы работа была
чистой, а ревью — быстрым.

## Порядок работы

1. Форкните репозиторий, создайте ветку от `main`:
   `git checkout -b feature/your-feature`
2. Вносите изменения.
3. Запустите все проверки (см. ниже) — они обязательны.
4. Коммит с понятным сообщением (описывает ЧТО и ЗАЧЕМ, не как).
5. Откройте Pull Request в `main`.

## Проверки (обязательно перед PR)

```bash
uv run ruff check app/ tests/
uv run mypy --strict app/
uv run pytest -v
pnpm -C web svelte-check
```

Все четыре должны быть зелёными.

## Правила кода

- **Абсолютные импорты** — только `from app...`, никаких относительных.
- **SSOT**: каждая сущность (провайдер, модель, ключ, бюджет) живёт в одном
  каноничном месте — БД/Redis + один модуль-владелец. Дублирование — баг.
- **Ноль костылей**: без `except: pass`, без временных хаков. Ошибки —
  значения (`AppError` с типом и статусом), не паники.
- **Логи**: не удаляйте существующие логи (помечайте `[existing]`),
  добавляйте. Никогда не логируйте `api_key`, `Authorization`, `key_hash`
  целиком (только первые 8 символов).
- **Секреты**: только плейсхолдеры (`YOUR_..._HERE`), `.env` в коммит не
  попадает.
- **Без хардкода провайдеров/моделей/промптов** — всё через БД.
- **`X-Request-ID`** и пагинация — в каждом API-ответе, где это уместно.

## Структура

```
app/
  api/v1/     # HTTP: публичные + admin роуты, MCP, middleware
  core/       # DB, Redis, ошибки
  services/   # translate, failover, dispatch, cache, плагины, MCP
web/          # SvelteKit админка
tests/        # pytest-asyncio
alembic/      # миграции
```

## Баги и вопросы

Открывайте issue с воспроизводимым шагом и версией окружения
(`uv --version`, `python --version`, `pnpm --version`).
